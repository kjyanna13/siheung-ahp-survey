# 시흥시 지역균형발전 전문가 AHP 조사 웹폼

배포 주소 : https://siheung-ahp-survey.streamlit.app/

「시흥시 균형발전 기본계획」의 **6개 분야 · 16개 전략 · 42개 핵심과제**(2026-09-08 보고서 기준)를
대상으로 우선순위사업 13개를 선정하기 위한 전문가 AHP 조사입니다.

---

## 1. 조사 구조

| 부 | 내용 | 응답 대상 | 분량 |
|---|---|---|---|
| Ⅰ | 응답자 정보 | 전원 | — |
| Ⅱ | 평가기준 K1~K4 쌍대비교 | **전원** | 6문항 |
| Ⅲ | 소관 분야 전략·핵심과제 쌍대비교 (K1) | 분야 전문가 | 분야별 6~15문항 |
| Ⅳ | 실행 가능성(K3)·파급효과(K4) 5점 평정 | 분야 전문가 | 분야별 4~10과제 |
| Ⅴ | 검토·자유의견·제출 | 전원 | — |

「균형발전 일반」·「관련 부서 공무원」은 Ⅱ부만 응답하고 Ⅴ부로 넘어갑니다.

### 분야별 계층 구조

| 분야 | 전략 | 핵심과제 | 블록 | 쌍대비교 문항 |
|---|---|---|---|---|
| 교통 | 3 | 9 | 4 | 13 |
| 주거환경 | 4 | 10 | 5 | 15 |
| 보건·복지 | 2 | 4 | 1 (평면화) | 6 |
| 교육 | 3 | 8 | 4 | 10 |
| 산업·경제 | 2 | 6 | 3 | 7 |
| 문화·여가 | 2 | 5 | 1 (평면화) | 10 |
| **계** | **16** | **42** | **18** | **61** |

보건·복지와 문화·여가는 전략층을 두면 2×2 블록이 과다해져 일관성 검정이 불가능한 블록이
늘어나므로, 전략층 없이 분야 내 과제를 한 블록에서 비교합니다(평면화).

전체 응답 항목 = Ⅱ부 6 + Ⅲ부 61 + Ⅳ부 42×2 = **151개**.
1인 응답은 소관 분야에 한정되므로 **25~35분**입니다.

## 2. 파일 구성

| 파일 | 역할 | 수정 방법 |
|---|---|---|
| `app.py` | 화면·흐름 | 직접 수정 |
| `criteria.py` | 평가기준 K1~K4 · 척도 · RI | 직접 수정 |
| `hierdata.py` | 분야·전략·계층 블록 | **자동 생성** |
| `taskdata.py` | 핵심과제 42개 | **자동 생성** |
| `ahpcore.py` | 가중치·CR·전이성 계산 | 직접 수정 |
| `storage.py` | Google Sheets 저장 | 직접 수정 |

`hierdata.py`·`taskdata.py`는 종이 조사표(docx)와 **같은 원본에서 생성**합니다.
계획의 과제 체계가 바뀌면 손으로 고치지 말고 생성기(`gen_webform.py`)를 다시 실행하십시오.
그래야 웹폼과 조사표가 어긋나지 않습니다.

`ahpcore.py`는 단독 실행하면 자기 점검을 합니다.

```bash
python ahpcore.py
# 완전일관 4x4 CR = 0.0
# 교과서 3x3 CR = 0.033
# 전이성 삼각형 1개 중 위반 1건
# RI[4] = 0.9
```

## 3. 응답 저장 — Google Sheets 연결

로컬 `responses/` 폴더에 쓰면 **Streamlit Cloud가 재시작될 때 응답이 사라집니다.**
반드시 아래 설정을 마친 뒤 조사를 시작하십시오.

### 3-1. 서비스 계정 만들기

1. https://console.cloud.google.com 에서 프로젝트 생성
2. **API 및 서비스 → 라이브러리** 에서 `Google Sheets API` 사용 설정
3. **사용자 인증 정보 → 사용자 인증 정보 만들기 → 서비스 계정** 생성
4. 만든 서비스 계정 → **키 → 키 추가 → JSON** 으로 키 파일 내려받기

### 3-2. 스프레드시트 준비

1. 구글 스프레드시트를 새로 만듭니다. 시트 탭은 앱이 알아서 만듭니다.
2. 주소 `https://docs.google.com/spreadsheets/d/★이부분★/edit` 에서 ID를 복사합니다.
3. 그 스프레드시트를 서비스 계정 이메일
   (`...@....iam.gserviceaccount.com`)에 **편집자**로 공유합니다.
   → 이 단계를 빠뜨리면 권한 오류가 납니다.

### 3-3. Secrets 등록

`.streamlit/secrets.toml.example` 을 참고해 값을 채웁니다.

- **로컬** : `.streamlit/secrets.toml` 로 저장 (깃허브에 올리지 않도록 `.gitignore`에 등록되어 있습니다)
- **Streamlit Cloud** : 앱 화면 우측 하단 **Manage app → Settings → Secrets** 에 붙여넣기

`private_key` 는 줄바꿈을 `\n` 으로 이어 붙인 한 줄 문자열이어야 합니다.

### 3-4. 저장되는 시트

| 시트 | 단위 | 용도 |
|---|---|---|
| `responses` | 제출 1건 = 1행 | 응답자 정보, CR, 전이성 위반 수, 의견, 원본 JSON |
| `pairwise` | 비교 1건 = 1행 | Ⅱ·Ⅲ부 쌍대비교 (부·블록·왼쪽·오른쪽·값) |
| `ratings` | 과제 1건 = 1행 | Ⅳ부 K3·K4 평정 |

`pairwise`·`ratings`가 long 형식이라 분석 코드에서 바로 읽을 수 있습니다.

### 3-5. 연결 실패 시

시트 설정 전이거나 오류가 나면 **응답은 유실되지 않습니다.**
제출 화면에 실패 사유와 함께 **응답 파일 내려받기(JSON)** 안내가 뜨며,
응답자가 파일을 받아 담당자에게 보내면 됩니다.

## 5. 응답자 편의 장치

- **진행 저장·이어하기** — 사이드바에서 진행 상황 JSON을 내려받고,
  첫 화면 「진행하던 응답 이어서 하기」에서 불러오면 이어서 응답할 수 있습니다.
  25~35분 조사이므로 중간 이탈에 대비한 장치입니다.
- **실시간 일관성 점검** — 블록마다 CR을 즉시 계산해 「적정 / 재검토 / 검정 제외」로 표시하고,
  재검토 시 판단구조와 가장 어긋나는 비교 3개를 알려 줍니다.
- **Ⅳ부 미응답 방지** — 기본 선택값 없이(`index=None`) 시작하며,
  빠뜨린 과제가 있으면 다음 단계로 넘어가지 않습니다.
- **평정 관대화 경고** — 평정 평균이 4.5 이상이면 화면에서 알려 줍니다.

## 6. 방법론 메모

- **평가기준은 K1~K4 4개** (2026-09-07 제3차 개정).
  구 「격차기여 유형」은 제4장 사업 분류값의 파생이고 그 판정 근거인 정량 취약도 진단이
  이미 제1층 분야 쿼터 산정에 쓰이므로, 제2층에서 다시 쓰면 진단이 두 번 반영됩니다.
  결과표에 병기만 하고 점수 산정·동점 처리에는 쓰지 않습니다.
- **Ⅱ부는 n = 4 이므로 RI = 0.90.** 자유도가 3으로 줄어 무작위에 가까운 응답도
  CR 0.10을 통과할 확률이 올라갑니다. 그래서 **전이성 검사(삼각형 4개 전수)** 를 병행하고,
  CR 통과 여부와 무관하게 위반 건수를 함께 기록합니다.
  Ⅱ부 CR 통과율이 높게 나오더라도 일관성이 개선된 것으로 해석하지 마십시오.
- **n = 2 블록은 CR이 정의되지 않습니다.** 척도 양극단(9) 쏠림만 점검합니다.
- **K2(주민 체감·수요)는 이 웹폼에서 수집하지 않습니다.** 통장 수요조사에서 산정해
  분석 단계에서 결합합니다. 산정은 ① 생활권 내 상대화 → ② 과제별 평균 →
  ③ 42개 전체 0~1 정규화 3단계이며, K2 결측 과제(13개)는 분야 중앙값을 대입하고
  결과표에 대입 여부를 표기합니다.
- **집단종합은 AIP 2단 층화**(분야 전문가 / 일반·공무원), AIJ 결과를 대조로 병기합니다.
- **CR 미통과 처리는 블록 단위 채택** — 미통과 블록만 제외하고 응답자 전체를 버리지 않습니다.
